## 实现与验收

| 项目 | 实现 | 实际验证 |
| --- | --- | --- |
| P01 请求级读取快照 | 正式目录和正文路由先验证 JWT 签名，单条 SQL 同时检查有效会话、账号状态、发布版本、有效定价、VIP、整本和稳定章节权益。权限按请求重新查数据库 | pgx query tracer 断言匿名预览、未购买预览、热缓存 VIP、整本和单章读取均为 1 条 SQL。冷 OSS 正文增加一次对象读取。冷 PostgreSQL 正文增加一次正文 SQL |
| P02 预览与全文分离 | 发布时保存最多半篇且最多 250 个 Unicode 字符的预览。预览查询直接读取短文本，只有已授权请求进入正文缓存和存储路径。HTTP 响应使用 private, no-store | 模拟 OSS 计数断言匿名和未购买请求不加载全文。验证退款后热缓存全文不返回给已失效 VIP，其他用户不能继承单章权益 |
| P03 回源生命周期 | DoChan 配合调用方取消与独立 4 秒加载上下文。回源并发有上限。按小说和章节保存固定容量的 2 秒负缓存，随机请求另受 IP 限流和请求准入约束 | 首个请求取消不撤销共享加载，等待者按自己的期限退出，过载返回 503。重复已确认缺失仅首次查询数据库 |
| P04 单章权益查询 | 正式读取快照使用稳定 chapter_id 的精确权益查询。清除原先 Redis 正权限集合的读写路径，每个读取请求重新确认权限 | 验证单章、整本、VIP、退款、账号封禁、会话过期和用户隔离。购买事务继续通过数据库唯一约束防重 |
| P05 发布与缓存粒度 | 正文缓存键使用内容 hash，历史正文使用稳定章节 ID、原位置和正文修订号。目录缓存保存无正文、无用户定价的轻量元数据。导入改为集合写入，仅释放移动或删除的章节位置，同位置未变化记录跳过更新。每书发布推进一次目录版本。调价和浏览量修改不推进目录版本 | 并发导入只接受一个版本。测试导入后的版本仅增加 1，调价和浏览量不增加目录版本，其他章节变更不导致已缓存正文回源。历史 inline 正文直接修改会推进修订号并清除旧 hash 和预览 |
| P06 批量进度 | 保留既有完整预校验、按小说去重、UNNEST 条件 UPSERT 和 100 条批量上限 | 全量 shelf 回归通过，覆盖较旧更新、相同时间版本比较、重复小说去重、失败整批回滚和非收藏进度 |
| P07 资源隔离 | 前台和支付后台使用独立 pgxpool，默认分别 21 和 4 个连接。阅读准入默认 48 个，正文回源默认 12 个，IP 默认 40 次/秒且 burst 80。Redis 故障冷却 1 秒，启动和 ready 允许有界回源 | 后台连接耗尽时前台仍可查询。Redis 熔断测试验证重复失败被抑制、冷却后恢复、普通 cache miss 不触发熔断。healthz 提供各池使用量、累计等待和取消次数 |
| P08 扣币并发 | 保留钱包行锁、小说共享锁、事务内报价复核、稳定章节购买记录和唯一约束 | 32 路同章只产生 1 次扣币。20 路不同章节争抢余额产生 9 次成功和 11 次余额不足。验证发布移位时旧报价拒绝、响应丢失后重复请求不重扣、真实隔离库充值入账与退款交错、订阅续费与扣费交错 |

P05 使用完整轻量目录接口以兼容当前 H5 调用，用户价格在请求内覆盖。目录列表仍需随章节数线性读取和序列化，大目录分页可按前端产品需求进一步实施。

## 迁移与上线

1. 使用新版 CMS 的 -migrate 应用 2026111703。迁移器先补齐尚未应用的 2026111702，再应用 2026111703。旧版本记录的 applied_at 保留，JWT 历史兼容窗口固定使用原始 2026111701 的切换时间。
2. OSS 正文部署运行 -backfill-chapter-previews，顺序扫描、每批读取 100 条元数据，每个对象限时 5 秒，上传引用和位置条件保护并发发布。失败记录写日志，命令返回非零，重试跳过已有预览。PostgreSQL 历史正文在查询时生成短预览。
3. 新增有效 VIP 索引通过 cms-backend/db/reader_query_indexes.sql 在事务外执行，已在隔离 PostgreSQL 上通过完整脚本入口验证。
4. 配套切换新版 CMS 和 Reader。数据库版本门槛保留。

回填尚未完成的历史 OSS 章节会显示空预览和付费墙，已授权读者仍可读取全文。短负缓存可能让刚发布或恢复上架的内容延迟最多约 2 秒可见。待复核历史单章购买继续执行上一轮保护策略。

## 验证结果与边界

Reader 和 CMS 均通过 go test -race -p 2 -count=1 ./... 及 go vet ./...。数据库回归在专用 PostgreSQL 16 容器执行，外部正文通过模拟 OSS 验证。并发索引脚本在独立测试库执行成功。

本轮没有连接生产 RDS、真实 OSS 或 PayPal，没有部署。上述 SQL 次数通过 tracer 实测，未测量生产 QPS、P50/P95/P99、WAL 和多机器分布式负载。并发消费由真实 Repository 的独立调用验证，未启动跨机器集群。Redis 恢复测试覆盖应用熔断状态和已有慢响应/连接池期限测试，未进行真实 Redis 集群故障切换。

运行参数与命令见 DEPLOYMENT_SOP.md 的阅读性能升级说明。单实例默认连接总量保持 25，扩容时需要结合 CMS、运维进程和 RDS 总连接预算配置。
