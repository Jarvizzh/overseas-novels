# Reader 付款、权益与退款：产品及客服规则

日期：2026-11-17。这是当前代码策略的说明与工单处理路径，不改变商品或退款政策。财务以经验证的渠道收据和退款记录为依据；Reader 状态、权益和营销事件各有用途。

## 1. 产品规则

| 场景 | 用户可见结果 | 账务与权益 |
| --- | --- | --- |
| 订阅审批通过、尚无扣款证据 | 等待付款确认 | 审批或 ACTIVE 状态本身不发放 VIP |
| 收据金额/币种已验证，付费周期缺少证据 | 付款进入人工复核，不要求用户重复付款 | 保留已扣款订单和诊断；不凭猜测延长 VIP，不产生该次未履约的 Purchase/Subscribe；已有其他已付有效权益继续按原期限使用 |
| 取消自动续费 | 停止后续续费，已付周期内继续使用 | CANCEL_PENDING 可重试；取消不立即截断已付周期，过期后自然失效 |
| 多份协议并存 | 每份本人协议可独立查询、取消 | 任一协议取消不自动替代或取消其他协议 |
| 整本购买 | 对该小说持续有效，包括后续发布章节 | 商品与小说以订单快照及证据为准；完整退款后撤回该整本权益；已独立解锁章节保持其自身记录 |
| 部分退款累计仍少于原 capture 全额 | 当前实现保留完整商品权益与充值金币 | 按 capture、币种和退款 ID 汇总去重，不按比例扣币或缩短 VIP，不将同一退款通知重复计入 |
| 部分退款累计达到原 capture 全额 | 执行完整退款后的撤权/扣币 | 事务内按原发放明细回收；同一 capture 的重复通知不会重复扣减 |
| 完整退款时金币已消费 | 不将余额扣成负数 | charged/bonus 分别扣除可用数；不足部分分别记入 shortfall，留给财务和客服跟进，不自动再次发起现金扣款 |
| 退款在付款补录/发货前先被验证 | 不再发放该笔金币或权益 | 先应用完整退款证据，再处理补录；不回放未履约的营销事件 |

退款渠道实际金额、手续费、汇兑等差额单独核对入账；不得通过重复发货、篡改商品快照或重复收款来平衡差额。Stripe 当前未开放，接口返回不可用。

## 2. 客服工单路径

### 已付款但无法阅读

1. 确认 Reader 用户 ID、协议/订单 ID、小说 ID、付款时间和币种；敏感凭证不收集到普通工单。
2. 财务核对当前绑定的 PayPal 账号/环境、capture/sale ID、经验证的实收金额、订阅 plan 和付费周期起止。支付截图只能作为线索。
3. 查看任务摘要及该订单的 reconciliation_note/error：区分待渠道确认、已付款未发货、周期证据不足、已退款和商品归属不符。
4. 网络或处理失败且证据完整：按工单使用 `payment-ops` 恢复指定任务或回退订阅游标，等待正常幂等处理，再核对权益和任务结果。
5. 证据不足：交财务/技术复核，补齐可追溯的渠道证据后经正式处理路径入账。不得直接改余额、改截止时间或用伪造事件补发；不得要求用户用再次付款解决本次确认故障。

### 取消仍显示处理中

1. 确认具体协议属于该用户，核对是否还有其他有效协议。
2. 查看 CANCEL_PENDING 的请求年龄、cancel_attempts、cancel_last_error；核对渠道是否已取消。
3. 网络恢复后由正常 worker 或按 ID 恢复任务继续确认；未确认前不得向用户宣称已成功停止续费。已经付费且未退款的周期继续有效。

### 部分退款、完整退款或金币不足

1. 按原 capture 和币种汇总渠道中每个已完成退款 ID，核对同一退款是否重放、是否仍有 Pending/Failed 退款。
2. 累计未退满时，向用户明确当前仍保留完整权益；不承诺按比例撤权。若产品希望采用另一政策，先修改产品定义、账务和验收规则。
3. 累计已全退时，核对订单 Refunded、退款记录 Completed、实际扣币交易和对应权益。退款渠道失败时应恢复既有有效状态，不能把失败请求当成完成退款。
4. 查看 charged_coin_shortfall/bonus_coin_shortfall。记录已消费缺口及财务处理结论；不得通过重放退款再次扣币，不得自动从后续充值追扣或将缺口当成新的付款订单。

### 历史整本、周期或归因无法证明

交财务/运营根据渠道账号、环境、收据及原商品/投放记录复核；保留证据引用和审核人。历史整本必须有商品与小说证据，不能仅凭同额收据推断。无归因 Outbox 不自动重发到新的 pixel；确认归因后需经单独审计的正式流程处理。

## 3. 回归依据

- `wallet/business_rules_test.go`：部分退款及重放保留整本/VIP；累计全退撤权；余额不负；不足记 shortfall；只扣一次。
- `wallet/settlement_integration_test.go`：完整退款、累计部分退款、并发退款、已付周期、退款间隙、未知周期记账、退款先到。
- CMS `billing/refund_test.go`：渠道退款失败恢复、权限及失败尝试审计。
- `wallet/remaining_fixes_test.go`：未知周期无 VIP/营销事件且可观测；补齐周期后只发货一次；旧订单不重放营销事件；多协议独立管理。
- `wallet/operations_test.go`：恢复约束、重试状态、租约/游标覆盖保护及监控摘要。

执行方法、上线顺序和验证边界见 [第 6 节优化验收](reader-backend-section-6-optimizations.md)。这些回归使用隔离 PostgreSQL 与渠道 mock，不能替代真实渠道验收。
