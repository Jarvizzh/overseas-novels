# Reader 第一、第二批修复说明

> **最终复验：此前发现的遗漏已追加修复并验证关闭。** 见[最终补充修复记录](reader-backend-remaining-3-closure.md)；下文为原批次实现记录。

对应审查基准 `34ff7cf` 的 R01–R12。修复包含 Reader API、共享 schema，以及必要的 Reader 会话续期和订阅管理交互；没有部署或调用真实支付渠道。

## 修复对应关系

| 问题 | 实现 |
| --- | --- |
| R01 游客身份到期 | 新增数据库会话、`POST /auth/refresh` 与 `/auth/logout`。刷新凭据为 32 字节随机值，数据库只保存 SHA-256；使用 HttpOnly Cookie，生产为 Secure、Host-only、SameSite=Strict。访问令牌仍为 72 小时，会话按使用续期至 180 天。新访问令牌关联会话，退出会撤销关联访问；有效旧 JWT 查询 profile 时补建会话。前端先恢复原身份，失效或异常时不悄悄替换已有账号。 |
| R02 绑定覆盖凭据 | Service 拒绝正式账号，SQL 条件更新再保护游客身份，冲突转换为领域错误；绑定和旧会话撤销在同一 SQL 语句中完成。正式账号修改邮箱/密码不复用游客绑定入口。 |
| R03 UTM 入账失败 | 订单字段扩展为 VARCHAR(100)，与用户/推广字段一致；验证长 campaign 可创建订单并记录订阅付款。 |
| R04 协议不可见 | 管理查询返回待审批、暂停、取消处理中及仍有效的已取消协议；VIP 布尔值独立用权威权益谓词计算。充值页显示协议状态及取消入口，取消处理中禁止重复点击。 |
| R05 状态补偿 | 对账先同步经验证的渠道协议状态，再导入交易，不再依赖某次交易是否新增。原取消意图及付费周期保护保留。 |
| R06 反馈失败 | 增加可选鉴权，匿名身份写 NULL，限制邮箱及正文，拒绝空白反馈，隐藏数据库错误。 |
| R07 进度覆盖 | UPSERT 在数据库内比较时间戳，旧写不能覆盖新写；收藏状态操作不再改进度时间。批次写入前验证章节、滚动范围和未来时间，迁移校正已有异常未来时间。 |
| R08 免费价继承 | 价格只用 NULL 表达继承，0 保留为免费。 |
| R09 推广身份混淆 | 用户保存服务端解析的推广 ID；报价、套餐、整本购买和付款归因使用同一解析函数。旧归因仅在 UTM 唯一匹配时回填，歧义不猜最新链接；已解析身份删除后不会改绑到同 UTM 的另一条链接。 |
| R10 空正文缓存 | 正文存储失败或为空直接返回错误，不写正缓存。 |
| R11 超长预览 | 所有排版统一按 rune 截断，预览不超过正文一半且最多 250 字符，另加省略号。 |
| R12 限流绕过 | 显式配置可信代理；默认仅信任 loopback 和当前 compose 网关。限流器按路由隔离、限制条目上限并回收空闲条目；注册及密码登录也启用限制。 |

## 配置和发布顺序

1. **先应用共享 schema，再启动新 Reader**。`cms-backend/db/schema.sql` 新增会话表、推广身份字段及解析函数，并调整 UTM 长度。CMS 嵌入该 schema；发布时必须确认 schema 执行成功，不能仅以 CMS 健康检查判断迁移完成。
2. 然后更新 Reader 后端及 Reader 前端。生产应使用 HTTPS、`GIN_MODE=release`；续期凭据不能写进 localStorage。
3. `TRUSTED_PROXIES` 为逗号分隔的可信代理地址/CIDR，可覆盖默认的 `127.0.0.1,::1,172.30.87.1`。最后一个地址对应当前 compose 网关；更换网络或采用额外 CDN/代理时必须按实际链路配置，不能信任所有公网地址。
4. CORS 允许请求自身 Host、`DEFAULT_DOMAIN`，以及显式 `ALLOWED_ORIGINS` 中的完整 Origin；开发模式额外允许本机 5173。跨站部署前端/API 时应调整为同站部署并验证 Cookie 策略，不能恢复任意 Origin 反射。
5. 历史游客若令牌已经过期且从未取得刷新凭据，不能根据 IP/设备字符串安全恢复原账号，需要独立的身份/支付凭证核验。此次不会猜测或合并这些历史账号。
6. 已有无会话字段的 JWT 继续兼容其原到期时间；新签发的会话关联 JWT 支持即时撤销。数据库只保存凭据哈希；每次创建会话会有界清理过期记录。

## 验证

- Reader `go test -race -count=1 ./...`：通过，包括隔离 PostgreSQL 中原有支付集成和新增可用性回归。
- 账号新增路径补充检查：正式注册、游客绑定、凭据哈希存储、刷新、过期拒绝、绑定撤销旧会话、退出撤销关联访问令牌；在最终修改后单独重跑账号 race 测试。
- Reader `go vet ./...`：通过。
- CMS `go test ./...`：通过。
- Reader 前端 `npm run build`、`npm run lint`：通过；新增前端代码执行过 Prettier，并保留原有无关代码排版。
- 新增回归覆盖：同来源伪造转发头、匿名反馈外键、旧进度覆盖、未来时间、0 价格、推广 ID 与重复 UTM、存储失败、超长正文预览、待审批协议可见性、渠道取消后的状态补偿、长 UTM 订单及订阅入账。

测试使用无业务挂载的临时 PostgreSQL 16；PayPal 状态查询由内存 transport 模拟。未做真实 PayPal/Meta 调用、线上迁移、浏览器多标签或多节点验收。原报告第三批 R13–R17 不在本次修复范围内。
